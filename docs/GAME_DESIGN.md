# Rebirth — 游戏设计定案

> 实现前先读本文与 `ARCHITECTURE.md`、`ROADMAP.md`。  
> 玩法定案以本文为准；未实现的系统只描述边界，不要求现在写代码。

## 核心定位

这是一款「剑与魔法 + Roguelike + 转生 + 世界事件」的动作游戏。

战斗体验参考 Brotato 一类自动战斗 Roguelike：

- 玩家主要控制**移动和走位**
- 普通攻击、技能、魔法、队友均为**自动执行**
- 玩家通过 **Build** 决定战斗方式

与传统 Roguelike 的核心区别：

> 每一次死亡都是一次人生结束。  
> 下一次游戏是新的转生。  
> 玩家是同一个灵魂，但每一世的选择会影响之后的世界。

## 玩家控制原则

- **不要**设计 QWER 技能栏。
- 玩家不主动按攻击键。
- 只有一个玩家实体 `Player`，不按职业拆成 Swordman / Mage / Assassin。
- 职业感来自武器、装备、技能、宝物构筑，而不是角色类。

## 长期游戏循环

```
转生 → 选择加护 → 进入冒险 → 战斗回合 → 经验/金币
→ 属性升级 → 商店 → 离开商店 → 奇遇 → 世界状态变化
→ 下一回合 → 魔王事件 → 继续冒险 → 死亡
→ 本世结算 → 跨转生数据更新 → 下一次转生
```

当前不实现完整循环。战斗系统必须与剧情/转生解耦，以便未来无限模式复用战斗。

## 本世 vs 跨转生

必须始终区分：

| RunState（这一世） | PersistentState（跨转生） |
| --- | --- |
| HP、等级、技能、装备 | 羁绊、剧情进度 |
| 金币、队友、地图进度 | 解锁、世界状态、转生次数 |

死亡时：结束 `RunState` → 产出 `RunResult` → 更新 `PersistentState` → 创建新的 `RunState`。

## 自动执行（未来）

技能/魔法未来支持：自动释放、条件触发、定时触发、命中/击杀/受伤触发、被动。  
当前只做武器自动攻击。

## 目标选择（未来能力）

最近、最低/最高 HP、Boss 优先、最近精英、随机、扇形、范围、背后、多目标。  
Phase 1：攻击范围内最近敌人。

## 内容体系（未来，数据驱动）

- 剑术 / 魔法 / 技能 / 装备 / 宝物 / 队友
- 羁绊 / 奇遇 / 世界状态 / 魔王 / 转生 / 主线 / 无限模式

技能新增应主要靠新的数据资源，而不是改核心 if/else。  
熟练度影响出现权重，但**不得锁死**高阶技能（保留极低概率 Jackpot）。

技能升级可以改变行为，并允许进化分支，而不是只做 `Damage +10%`。

## 商店（Phase 3 最小实现）

当前：4 个随机属性商品，购买 / 刷新 / 价格 / 加权随机。商店不解析效果，只提供货架。  
未来货架可换成 Skill / Treasure / Equipment / Companion，不必改商店流程。

## 魔王（未来）

不是固定最终 Boss 角色，而是 `DemonKingSystem + DemonKingState + HostCharacter`。  
可能换宿主、逃走变强、被他人击败后重新出现。

## 奇遇（未来）

战斗回合后：商店 → 奇遇。  
奇遇改 WorldState / Companion / DemonKing / 奖励 / 后续事件。  
必须数据驱动，不写死在 GameManager。

## 当前 Phase 1 体验（已定案的最小可玩）

- 中立占位角色：移动、HP、死亡
- 一把剑：自动攻击、范围、攻速、基础伤害
- 一种近战敌人：追踪、接触伤害、HP、死亡
- 持续刷怪；击杀掉 XP 与金币
- XP 满：暂停并出现 3 个动态生成的属性选项（攻/攻速/移速）
- HP=0：结算存活时间、击杀、等级、金币，可重新开始

Phase 1 **不做**：魔法、技能、装备、宝物、商店、队友、羁绊、奇遇、转生、魔王、剧情、无限模式、正式美术。

## 当前 Phase 3 体验

- 每回合战斗 60 秒（`CombatLoopConfig`）
- 时间到：清场 → 本回合攒下的升级一次选完 → 商店
- 战斗中升级只涨等级与经验，不打断战斗
- 4 个随机商品，可用本局金币购买；可花金币刷新；可空手离开
- 当前商品是属性修饰（攻击/攻速/移速/生命等），不是技能/装备系统
- 离开商店后开始下一回合，HP/等级/已购加成保留
- 玩家死亡仍立即结算，不进商店
