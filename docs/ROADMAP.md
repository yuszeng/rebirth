# Rebirth — 开发路线

当前阶段：**Phase 5a（装备栏 + 背包）进行中**。  
玩法已定案转向 **2D 3/4 + 房间相机 + 手动房间战**（不做 3D）；**对应 Phase 5b–5e 未接到明确指令前不要开始**。  
Phase 6+（魔法、宝物、队友、奇遇、转生等）同样需明确指令后再做。

规则：

1. 只实现当前被批准的 Phase 范围。
2. 完成后必须可运行，再等待人工指令进入下一 Phase。
3. 新 Phase 不能破坏旧 Phase（无技能也能打、无装备也能跑、无队友也能战、无剧情也能打）。
4. 开始新 Phase 时：先读 `GAME_DESIGN.md`、`ARCHITECTURE.md`、本文，再在现有架构上扩展。

## Phase 1 — 基础战斗 MVP（已完成）

- 玩家移动、HP、死亡
- 剑：自动攻击、范围、攻速、伤害
- 一种数据驱动近战敌人：追踪、接触伤害
- 持续刷怪
- 击杀 → XP、金币
- 升级选项动态生成（Phase 1 为攻 / 攻速 / 移速；战斗中弹窗后改为回合结束再选）
- Game Over 结算（存活时间、击杀、等级、金币）+ 重开

验收：Godot 打开 `scenes/main.tscn` 可完整进行一局。

## Phase 2 — XP + 属性成长（已完成）

在现有升级管道上扩展选项池（生命、暴击、闪避、范围等），不另写一套升级 UI。  
选项由 `content/upgrades/*.tres` 扫描加载。防御、暴击、闪避、吸血、伤害加成已进入 `DamageSystem`；范围/弹速/持续加成会影响对应攻击。法力与幸运仍无独立系统。

## Phase 3 — 商店 + 金币（已完成）

独立 `ShopService` + `ShopPanel`。战斗回合结束 → 清场 → 本回合待选升级一次选完 → 进店。  
商品是抽象可购买项（属性修饰或武器），商店不解析效果内部。金币走 `RunState` / `Wallet`。支持购买、刷新、空手离开后进入下一回合。战斗中升级只记账、不弹窗。玩家死亡立即结算，不进商店。

验收：Godot 打开 `scenes/main.tscn`，打完一回合可进店买/刷/离开，下一回合 HP 回满且等级与已购加成保留。

## Phase 4 — 攻击方式与武器商店（已完成）

数据驱动 `WeaponData` + `AttackController`。开局选一把武器，商店再卖尚未拥有的武器；按 E 在已拥有武器之间切换。升级池仍只出属性。  
武器共用 `AttackPattern` 底层模式，禁止用武器 Id 字符串判断攻击逻辑。没买额外武器的一局仍可打完。不做 QWER 技能栏、法力、命中触发、进化。

验收：商店买到武器后可按 E 切换；已拥有武器不再上架；只带开局武器也能打完一局。

## Phase 5 — 装备 + 模块化外观（5a 进行中）

槽位：头部、手部、胸部、裤子、鞋子、武器。  
护甲是 `EquipmentData`（`StatModifier` + 占位外观色）；武器槽只接受已有 `WeaponData`，不另做一套攻击。  
本局背包记下买过的护甲与武器；商店页同时显示六格装备栏和背包。空槽/空背包仍可打完一局。

- 属性商品不进背包（不是可装备物）。
- 同 Id 护甲/武器买过一次后不再上架。
- 槽空则购买后自动穿上；槽上已有物时新件进背包，可在商店页点击背包切换。
- 同槽替换：旧件留在背包，只卸下属性。武器不能卸成空手（至少保留开局武器）。
- 按 E 切换攻击方式时，武器槽与当前武器同步。

不做：强化、套装、掉落、战斗中换装、仓库拖拽。  
不做：改相机、改成 3/4 人形、房间墙体、手动攻击（那些是 5b–5c）。

## Phase 5b — 3/4 样板房 + 房间相机（已定案，未批准开工）

停用无边大竞技场作为目标体验。一间有墙、出生点、北侧门的 2D 房间；`Camera2D` 锁定整房入画；角色/敌人/装饰 Y 排序；占位人形 + 面向。仍可暂时保留自动攻击，只验收「看起来是房间舞台」。  
禁止 Godot 3D。无技能栏、无商店改版要求。

验收：运行主场景能看见一间 3/4 房间，而不是高空俯视圈地。

## Phase 5c — 手动普攻与冲刺（已定案，未批准开工）

`AttackController` 改为按键 + 冷却才打，朝向用面向。冲刺位移 + 短暂无敌；受击短硬直。至少两种敌人节奏（可躲前摇，不只贴脸秒伤）。复用现有 `AttackPattern`，不新写伤害管道。  
E 切武器可保留，但不再作为「切换自动技能」。

验收：同一间房里，会打会冲能清场，站着挨打会输。

## Phase 5d — 房间流（已定案，未批准开工）

`SpawnDirector` 改为本房波次；清场开门；2～3 出口（再战斗 / 商店 / 事件占位）。线性 4～6 房即可。用清房替换 `CombatLoopConfig` 计时进店。商店复用 `ShopService` / `ShopPanel`。不要并行保留圈地生存主循环。

验收：一局是一串房间，死亡仍走现有结算。

## Phase 5e — 按键技能（已定案，未批准开工）

`SkillData` + `AttackPattern` 绑到副攻击/投技键；关掉 `SkillController` 自动循环。不要做 QWER 满栏。没买技能时只靠普攻仍能打完。

## Phase 6 — 魔法系统

与技能并列的**玩家触发**施法，走同一套 Targeting / Damage / Pattern。不做第二套自动扫场。

## Phase 7 — 宝物系统

Treasure 作为效果来源（Modifier + 事件监听），不是新战斗循环。

## Phase 8 — 队友系统

独立 Companion 实体。没有队友时战斗不变。队友 AI 另定，不要把玩家操作改回全自动。

## Phase 9 — 奇遇系统

数据驱动 Encounter，挂在事件房或门后选择上。不要把事件写进 GameManager 的巨大 match。

## Phase 10 — 转生 + PersistentState

RunResult → PersistentState → NewRunState。严格分离本世与跨世数据。

## Phase 11 — 羁绊 + Companion Story

BondLevel / BondXP / 故事解锁。可作开局队友，但不锁死战斗。

## Phase 12 — 世界状态

事件驱动 WorldState（魔王、同伴、剧情旗标），不做全图 NPC 模拟。

## Phase 13 — 魔王系统

DemonKingSystem + State + Host，不是 `FinalBossDemonKing`。

## Phase 14 — 主线剧情

Story 与 Combat 解耦。无剧情时战斗仍可运行。

## Phase 15 — 无限模式

解锁后复用 Combat / Content，不依赖完整剧情。
